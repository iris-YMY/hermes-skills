# 叙事与沟通框架（Narrative & Style Guidelines）

> 来源：OpenAI `presentations` skill 的 style_guidelines.md，经 Hermes 适配。
> 适用于每一份 deck。用户明确指示或提供的参考材料优先于这些默认值。

## 1. 先定义沟通任务（Communication Job）

在选择幻灯片、版式或视觉素材之前，先推断：

- **目标受众**：不要假设受众就是用户本人。
- **这份 deck 的任务**：教育、说服、销售、推荐、促成决策、辅助讨论。
- **受众的期望结果**：看完后他们应该理解、相信、选择、批准、讨论或做什么。
- **核心结论** 与支撑它的关键主张/证据。
- **用户需求中的每一项内容要求和来源约束**。

用一句话表达沟通任务：

> 最终，**[受众]** 应该 **[结果]**，因为 **[核心结论]**。

对于探索性/参考性 deck，改为定义受众离开时应带走的问题或理解，而不是强行给出建议。

## 2. 选择恰当的叙事弧（Narrative Arc）

- 上下文 → 利害 → 证据 → 影响 → 行动
- 问题 → 分析 → 答案
- 问题 → 原因/选项 → 建议
- 现状 → 变化 → 未来
- 时间线、流程、学习进阶，或 主张 → 证据 → 推论

**议程表不是叙事**。序列要有累积性，让每一部分为下一部分铺垫。不要把说服性或情绪化弧线强加给技术性/参考性 deck；用逻辑、因果、时间顺序或决策流来构建。

## 3. 每一页都要推进故事

- 每页只有一个叙事任务 + 一个核心主张。
- 标题用**结论式标题**（表达观点，而非仅命名主题）。
- 页序要让每页回答上一页提出的问题，或引出下一页要解决的问题；逻辑跳跃时加过渡页。
- 把被要求的主题融入主线；删掉重复的节拍、冗余的总结、不推进主线的内容。

## 4. 把证据转化为意义

- 不要像清单一样罗列事实/指标/图表/例子。对每条重要证据，说明它**意味着什么、为什么对这个受众重要、如何改变结论/决策/下一步**。
- 图表和视觉必须强化当前主张。
- 只有在能实质提升理解时才使用接地气的例子、场景、案例、人的影响。
- **绝不虚构**人物、引语、事实、数据或结果。

## 5. 刻意地开头与结尾

- **开头**：用上下文、目的、利害、问题或张力开场，让 deck 值得关注。
- **结尾**：用相应的结果收尾——建议/决策、明确的行动、综合与应用、或影响与有价值的问题。
- 不要以细节、技术产物、未总结的概要或通用 "Thank you" 页突兀结束。

## 6. 面向受众的自然文案

- 可见文案服务目标受众。不暴露模型指令、规划笔记、时间轴脚手架、讲稿或实现细节（除非用户明确要求）。
- 标题和正文用直接、具体、自然的语言：具体主张、主动动词、大白话；避免空泛口号、行话、抽象名词堆砌、虚张声势。
- 避免公式化结构：重复的 "从 X 到 Y" 标题、标点模式、平行结构、广告式碎片。
- 标题要说人话——一个真人 presenter 会脱口而出的话。如果听起来像提示词、制作注记、口号生成器或机械模板，重写。

## 7. 版面构成

- 全 deck 使用连贯的视觉系统，同时变化页面剪影以适配内容。
- 标题页保持极简。
- 优先**低密度、高价值**页面。缩短文案或换版式，而不是缩小字号。
- 版面干净均衡；避免拥挤与过度留白；默认左右边距相等。
- **用一个构图，而不是一组 UI 面板**。避免卡片网格、pills、徽章、按钮式文本框、标签/导航模式、密集仪表盘风格，以及其他暗示交互性的组件库美学。少用花哨文本框，画布上保持扁平结构。
- 除非内容需要刻意变化，否则保持配色、排版、间距、对齐和视觉处理的连贯性。

## 8. 排版与适配（硬性要求）

当用户没有提供明确样式指导时，至少使用：

- **50 pt**：deck 主标题
- **35 pt**：页面标题
- **24 pt**：副标题、callout 标题、文本框标题
- **16 pt**：正文

检查意外换行。**绝不允许**本应一行的标题/横幅换成两行。叙事文案必须适配所选版式；缩短文案或换版式，而不是增加密度或把字号降到下限以下。

## 9. 图表与视觉素材规则

- **不要用 Python 画图**；不要用程序化矢量形状做视觉；不要用任何程序化绘制。用图片搜索或 image_gen 工具。
- **少用图表**：仅在用户要求或单个图表能实质提升复杂概念清晰度时使用。
  - 简单图表：用 PowerPoint 原生形状。
  - 复杂关系/拓扑/网络图：用 Graphviz。
  - 高审美/说明性/科学信息图：用 image_gen。
  - 使用原生形状+连接线时：**先建连接线（箭头/边），再建实体节点**，让边出现在节点后面，不穿过节点形状或标签。
- 获取/生成视觉素材前，考虑目标宽高比、摆放位置和裁剪选项。例如图片左侧要放文字、图中有人的话，应让 image_gen 把人放在图片右侧。
- 默认**不重复使用同一张图**（除非是背景）。
- 检查最终图片在整页尺寸下的裁剪效果；替换模糊、变形、构图差或与 deck 风格不一致的素材。
- 图表标签保持简洁、层级清晰、连接线语义一致。

## 10. 引用与来源

- 在演讲者备注中为每一条外部来源素材和每一条非平凡的外部主张添加 `[Sources]` 块。
- 来源要可追溯；研究支撑 deck 时，注明引用来源。
