# 品牌电商提案 PPT 审查与改造

## ⛔ 交付顺序铁律（用户明确纠正，2026-08-07）
**先给 review → 用户说 OK → 才动手出 PPT。** 绝不直接产出改好的 PPT 文件。
- 用户原话："第五点是先给我 review，我 ok 了再出 ppt"
- 背景：曾直接交付改造后的 PPTX 被"不对不对"驳回。review 形态 = 逐页意见表（页码/现状/处理建议）+ 调研数据支撑 + 需用户拍板的点，而不是一个新 PPT 文件。
- 确认理解时用"我的任务理解"清单式复述，让用户逐条确认（"其他四点是对的，第五点是先给我 review"）。
- ⚠️ **用户可能要求"先出设计稿 → 确认 → 再画 PPT → 再图片 review 排版"（2026-08-08 v8 流程）**：用户原话"你给我看你的ppt设计，我觉得可以之后，你再画ppt，然后给我图片review待我排版"。流程 = ① 文字版逐页布局设计表（每页区块/卡片/配图/底部条）+ 用户逐条反馈裁剪内容 → ② 画 PPTX → ③ 渲染 PNG 发图 review 排版 → ④ 确认后交付文件。设计稿阶段用户会给明确的**内容裁剪指令**（如"P3 去掉站内付费/截图占位"、"P4 不要 KPI"、"P5 不要货盘四层"、"P7 外部数据换成天猫策略内容"），逐条记录别遗漏，也别自行加回被裁内容。
- **Review 分两轮（用户流程确认，2026-08-08）**：①**设计稿确认**：画 PPT 前先给文字/表格版逐页设计稿（每页布局区块 + 内容要点 + 配图方案），用户说"可以"才动手画；②**图片 review**：画完后渲染 PNG 待用户排版确认。用户原话："你给我看你的ppt设计，我觉得可以之后，你再画ppt，然后给我图片review待我排版"。设计稿阶段曾被质疑"你是不是只写文字？不会放图片？"→ **设计稿里必须写明每页配图方案**，不能只有文字卡片规划。
- **对外完整版 = 必须有图**（2026-08-08）：可对外 present 版本不能是纯文字卡片。LB 提案配图来源：`/tmp/lb_files/tpl_imgs/`（image19-25=572×800 产品/模特图、image13=3128×4692 高清大图、image15=2000×2800 章节页图）。用户说"不用留位置 / 不需要保留截图部分"时 = **用真实品牌图正常生成完整页**，不是留灰块占位框。
- **内容替换偏好**（2026-08-08）：最新版策略文档有对应内容时，外部市场数据（如 2024 店播 GMV 64%/份额 69.5%）**替换为文档内策略内容**（如店播=天猫长期内容核心/六档固定栏目/达播红线）。用户会逐页点名删减模块（例：P3 去站内付费+截图、P4 去 KPI、P5 去货盘四层承接）——**逐条记录用户删减项，不要自行发挥加回**。

## ⚠️ Review 要出图片（用户二次纠正，2026-08-07）
用户原话："review 的话，你是要出图片给我哦，你看下 ppt review 的 skill"。
- **review 交付形态 = 渲染成图片发对话**（MEDIA: 语法），不是文字表格，也不是 PPTX 文件链接。
- 流程（presentation-visual-director skill）：工作 PPTX 内部保留 → soffice --headless --convert-to pdf → pymupdf get_pixmap(dpi=110) 逐页渲染 PNG → MEDIA:/path.png 逐页发对话 → 用户确认后才交付 PPTX。
- 用户看图的重点：整体风格贴不贴模版、占位图位、待补数据位置、内容方向。每张图配一句说明 + 明确要用户拍板的点。
- 图片位/数据位先放灰色占位框（如 [IMG] 等待小艾提供截图、[ 覆盖率精确值 等待数据 ]），不编造。
- ⚠️ **MEDIA:/path.png 在本飞书通道不渲染**（用户实测"看不到图片哇"，2026-08-07）。兜底：PIL 拼 3×3 总览大图 → `drive/v1/files/upload_all`（user OAuth token，parent_node 用根目录 token `nodcnnkM2lJvS2xjFQBBBRT4Eeg`）→ 发云空间链接 + 图上标注每页位置对照说明。无效 parent 报 1061044 "parent node not exist"。
- ⚠️ **页数必须精确**：用户要 9 页就只给 9 页，绝不可"模版 21 页 + 新增 9 页"拼成 30 页交付（用户原话："不是为什么要生成30页，我需要只有9页啊"）。
- ⚠️ **分点排版，不要大段文字（用户三纠，2026-08-07）**：用户发批注图红框圈出页面，原话"把你的文案画成ppt版式，需要贴图的部分留下灰色块块给我，要学会分点排版论述，不要大段文字输出"。要点：
  - 每页结构 = **"▍小节标题 + • 要点"**（小节标题用主色加粗，要点用圆点列表），严禁整段长文本块。
  - 需要贴图的位置（原图或用户待提供截图）**一律留灰色虚线占位框**，框内标注要贴什么图（如 `[IMG] STORE TRAFFIC STRUCTURE CHART`）＋备注（原图待嵌入 / 等待小艾提供截图）。
  - **"内容不动"的正确解读**：保留**所有**文案信息和图片，用户原话："不用动的意思就是所有文案和图片都要留下来"。两种可接受处理（依用户指定基准版本而定，2026-08-07 最终定案 v7）：
    - **整页嵌原图 + 底部 LB 页脚条**（v4 方式）：用于完全保留原页面视觉的页。最终 P2/P6/P8/P9 采用此处理且被用户认可（用户指定 v4 为基准，其他页保持不变）。
    - **原文案提取成分点要点 + 图片位置留灰色块**：用于需要重排文案的页。最终 P3/P4/P5/P7 采用卡片式分点重排。
    - 最终结构：v7 = v4 基准（P1 章节页 + P2/P6/P8/P9 整页嵌原图 + LB 页脚）+ P3/P4/P5/P7 卡片式重排（覆盖率大数字、2×2/3×2 卡片网格、推荐结论条 + 数据卡片）。用户按此结构评审。
- ⚠️ **内容页必须配图，纯文字卡片会被质疑（用户四纠，2026-08-08 v8）**：用户原话"你是不是只写文字？不会放图片？"——重排的内容页绝不能只有文字卡片，必须配品牌产品图做视觉支撑。素材在 `/tmp/lb_files/tpl_imgs/`（image19-25 产品图 572×800、image13 高清 3128×4692、image15 章节大图 2000×2800、image3/4/5 792×1108），布局用"左侧竖图 + 右侧卡片"（v8 P3/P5）或"2×2 卡片 + 右侧大图"（v8 P4）。配图前先盘素材清单确认可用图（尺寸/内容），别默认"没图可放"。
- ⚠️ **卡片标题用英文、内容用中文**（2026-08-08 v8）：LB TEMPLATE 卡片标题统一英文（如 `STORE STREAM = TMALL CONTENT CORE`、`SIX FIXED COLUMNS 六档栏目`），要点内容中文；中文标题在 Century Gothic 下渲染可疑（OCR 出现乱码），且不符合模版风格。

## 📍 用户批注图定位（vision 不可用时，2026-08-07）
用户发带红色框框的批注图（如圈出要改的页面），但本环境 vision_analyze/browser_vision 报 400 deserialize（auxiliary.vision 是纯文本模型）。兜底链路：
1. **红色像素聚类**：PIL+numpy 计算 `red_mask = (r>150)&(g<100)&(b<100)&(r-g>60)`，BFS flood-fill（step 2）找连通域，得到每个红框 bbox。
2. **9 宫格映射**：若图是 3×3 拼图截图，按缩放比例还原每格（页面）坐标，统计每格红色像素量（>500 即被圈）。本例 P2-P9 全被圈、P1 未圈 → 用户要改内容页不动章节页。
3. **OCR 佐证**：tesseract -l chi_sim+eng 提取页面标题确认是哪些页。
4. 判读后再动手，别猜。
5. ⚠️ **红框自动检测会过度圈选**：第二次批注图红色像素检测把 P2-P9 全标为"圈中"，但用户实际只圈 3/4/5/7（红框粗/跨格导致）。**以用户文字点名的页码为准**，像素检测只做佐证，别全信。
6. ⚠️ **版本锚定**：用户可能引用**早期版本**做基准（原话："是在 LB OPERATION TRAFFIC v4 的版本上面，重做 P3/P4/P5/P7 四页，其他页保持不变"），即使最新交付的是 v5/v6。开工前必须确认：批注基于哪个版本？重做哪几页？其余页保持该版本原样——**绝不拿最新版当底**。

## 任务拆解模板（改造型提案）
输入通常为：① 风格模版 slides（只做格式参考）+ ② 内容 slides（含待改造页）+ ③ 补充文件（商品表/PDF 预读）。
典型逐页要求（用户给出时逐条记录，别自行发挥）：
- 某几页：**按模版改格式、内容不动**（最常见）
- 某几页：**换品牌图**（如 JACQUEMUS 图 → ZARA/COS/&Other Stories 图）
- 某几页：**换品牌 + 需调研**（如 PDP 内容特点/分类/占比、达播决策）
- 确认理解时先复述"逐页改造要求表"，用户确认后才开工。

## 执行步骤
1. **飞书 slides 读取**：`POST /drive/v1/metas/batch_query` + `doc_type:"slides"`（docx/file 报 970005）；导出走 export_tasks（body 必须带 `sub_id:""` 否则 400）+ medias 下载。详见 feishu-hermes-integration skill。
2. **分析模版**：python-pptx 读取模版每页 shape/字体/颜色/图片数量（章节页 vs 内容页交替布局）。记录：字体名（如 Century Gothic）、标题字号（如 32pt）、主色 RGB、章节页左图+右标题布局。
3. **调研支撑**（Tavily，见 web-research skill）：
   - 竞品品牌 PDP 短视频规范（如 ZARA：15-60s/720p+/≤1.5GB）
   - 达播/店播数据（2024 淘宝店播 GMV 64%、份额 69.5% → 店播为主+中腰部达播为辅）
   - 品牌调性（如 Love Bonito：亚洲女性/empowerment/社区感）
   - ⚠️ 数据必须真实可溯源；查不到的覆盖率类数据标注"待补充/行业参考（AI推测）"，不编造。
4. **产出 review**：逐页意见表 + 调研数据 + 待拍板问题清单（哪些图需要用户截图、哪些数据需用户确认方向）。
5. **用户 OK 后出 PPT**：python-pptx **新建空 Presentation() 从零画**（见"关键坑"），先 `prs.slide_width/height` 设 16:9（12192000×6858000），复刻模版视觉常量（Century Gothic、32pt 章节标题、主色、红条+标题+正文布局），新增页按"章节页/内容页"两种版式生成；占位框用灰底虚线框。可复用工具函数（add_pic_fit 等比插图 / add_card / add_top_bar / add_bottom_strip / add_original_page / 素材盘点 PIL 方法论 / 批量上传云空间脚本）见 `references/pptx-drawing-utils.md`——**直接复制使用，别重新发明**。
6. **图片版 review 迭代**（用户看图后可能发红框批注图）：先按"用户批注图定位"解读圈了哪些页 → 按批注改对应页 → 重新渲染 PNG → 拼 3×3 总览 → 上传云空间发链接。每轮只改批注涉及的页面，其余不动。用户确认后才交付 PPTX。
   - ⚠️ **渲染后先自查再发图**（2026-08-08 v8）：soffice→PDF→PNG 后，用 `tesseract -l chi_sim+eng` OCR 每页检查文字是否完整渲染（标题丢失/文字溢出/乱码会暴露），重点看中文字符（Century Gothic 下中文标题可能渲染异常）。OCR 的乱码要区分"渲染问题"与"识别引擎误读"——中文识别误读常见（如"逛逛"→"WERE"），可通过放大裁剪局部区域单独 OCR 复核。
7. **QA 验收**：交付前按 `ppt-production-qa` skill 统一验收标准自检（渲染逐页检查、排版可读性、视觉对齐、数据与来源一致性；TP 提案为可编辑 PPTX 则按 editable-pptx 门槛：native-chart + 内嵌工作簿、noAutofit、≥12pt）。PASS / PASS_WITH_APPROVED_EXCEPTIONS 才允许交付。
8. **交付**：PPTX + 转 PDF 预览版；飞书不能直接 MEDIA: 发文件，用 `drive/v1/files/upload_all`（user OAuth）+ 发链接。

## 关键坑
- 飞书 slides 是独立 doc_type，`lark doc get` / docx API 无效（1770002）
- IM 附件下载大文件报 234037 → 让用户传云空间再 drive 下载
- 有权限问题先找用户（用户明确说"有权限问题先找我"），别自己闷头重试
- 用户给的飞书云文档要主动检查可访问性，别跳过这步直接干活
- 交付物命名区分：review（文字意见）vs 改造版 PPTX（用户确认后才出）
- ⚠️ **python-pptx 删除模版 slide 会损坏文件**：`prs.slides._sldIdLst` 直接 remove 会产生 zip duplicate name 警告，LibreOffice 转换报 "source file could not be loaded"。**正解：不删模版页，新建 `Presentation()`（空文件）+ 手动设 16:9 尺寸 + 用默认 BLANK layout + 复刻模版视觉常量（字体/字号/主色/章节页布局）从零画页面**。这样产出干净的 N 页文件，绝不混入模版页。
- ⚠️ **图片直接 add_picture 传宽高会拉伸变形**：必须先用 PIL 读原尺寸，按 `min(max_w/w, max_h/h)` 等比缩放再居中（函数见 `references/pptx-drawing-utils.md` 的 `add_pic_fit`）。
- ⚠️ **箭头符号（→/←）在 Century Gothic 下可能渲染为方块**：PPT 内用 `→` 可行（LibreOffice 渲染正常），但避免使用 emoji 和特殊 Unicode 符号；中文用全角标点。
- ⚠️ **emoji 零容忍（2026-08-10 实测）**：标题里的装饰星号 ⭐ 在 Century Gothic 下也渲染成乱码（OCR 出「侦/南」）。装饰标记一律用文字（如「烈儿宝贝（首选）」），任何 emoji/特殊符号都不要用。
- ⚠️ **多行卡片区必须核算累计坐标（2026-08-10 实测）**：内容区固定 1450000–6000000 EMU。多个 2×2 卡区堆叠时先算每行 `cy = 首行 + row×(cah+gap)`，确保末行底部 ≤ 6000000。v9 P7b 首版 mid 区算到 7420000，超出页高 6858000 → 4 张卡中 2 张被静默裁剪（OCR 只识别出前 2 张才暴露）。**OCR 自查判读**：卡片「缺失」= 真实裁剪（必须修坐标）；中文「误读」（生类=垂类、Legay=Leggy、Mar=万粉）是 OCR 引擎小字问题（可忽略）。
- ⚠️ **在已交付 deck 上加新页**：用户要求把新 research 织进既有方案时，先给设计稿二选一（方案 A 新增 1 页 vs 方案 B 并入现有页），用户确认页数变化后，复制最新 gen 脚本在目标页位置后插入新 slide block（如 P7 后=P7b），其余页 block 原样保留零改动。

## 🖼️ 图片页元素全量盘点 SOP（2026-08-13 沉淀，JD 1+1 任务教训）

**触发**：整页是图片的 slide 要重构成可编辑内容时。**禁止只做一次整页 OCR 就动手重构**——会漏掉小字号标签、图例、坐标轴标签、第二个图表/表格。

### 教训（根因）
JD 1+1 任务 P5 图片页首版只 OCR 出「韦恩图 + 各人群占比表」，漏掉：年龄分布柱状图（0-15→56-60 岁）、「仅购买自营/POP」标签、「26-35 岁占比超50%」结论、「自营可追溯更多学生用户」、「自营与POP PLUS分布」第二个表。被用户逼问 3 轮才补全。根因 = ① 只整页 OCR 一次 ② 无元素清单 ③ 数字读不清就静默丢弃。

### 强制流程（按序执行，不可跳过）
1. **跑全量盘点脚本**（不要手写一次性 OCR）：`python scripts/ocr_slide_exhaustive.py <原图.png> --grid 3`。脚本自动做 4 手段并集：超分（<1500px 图 LANCZOS×4+锐化2+对比1.5）、网格化逐格、多阈值二值化（100/140/180）、反色。每格每手段输出一份，逐份读。
2. **建元素清单**（重构前必须列全，逐类核对）：
   - 图表类：有几个图（韦恩图/柱状图/折线图/饼图）？每个图的标题、坐标轴标签、图例、数据系列值。
   - 表格类：有几个表？每个表几行几列、行标签、列标签、数值。
   - 文本类：标题、结论条、标签、图注、来源。
   - 图例/图注：如「仅购买自营」「仅购买 POP」「自营更优/POP更优」这类小字最易漏。
3. **表格逐行精读**：先读行标签列，再逐行读数字；读不清的单元格标「—」占位，但**行列结构必须完整**。
4. **数字读不清的兜底**：局部裁剪放大 + 反色 + 多阈值重试；仍读不出 → 标「待补」，**绝不静默丢弃**，并在交付说明里明确列出哪些数字待补。

### 交付前自查清单
- [ ] 所有图表已盘点（标题/轴/图例/数据系列）
- [ ] 所有表格已盘点（行列结构完整，不只读第一个表）
- [ ] 所有小标签/图例/图注已提取
- [ ] 结论性文字已保留（如「占比超50%」）
- [ ] 读不清的数字已标「待补」而非丢弃，且已在交付说明列明

## 飞书 wiki 节点解析（用户发 wiki 链接时，2026-08-07）
用户发 wiki 链接（如 `.../wiki/U1q3wm1nWi6yIlkvYtgcZvSZn0e`）补充资料时：
